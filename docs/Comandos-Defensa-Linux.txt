0. ANTES DE LA DEFENSA (una sola vez, en este orden)

0.1 Docker abierto. Compilar el JAR y levantar contenedores
mvn package -DskipTests
SMTP_PORT=2525 docker compose up -d
docker compose ps

0.2 Solo la primera vez (o tras "docker compose down -v")
chmod +x scripts/*.sh
./scripts/crear-usuarios.sh
./scripts/crear-bd.sh
Si da "bad interpreter" o $'\r' (finales de linea de Windows):
sed -i 's/\r$//' scripts/*.sh

0.3 Verificar que todo anda (8 de 8 PASS, ~4 min). OJO: deja Flowable SIN modelo
export SMTP_PORT=2525
node scripts/escenarios/m-escenarios.js

0.4 Desplegar DMN + modelo
./scripts/desplegar-modelo.sh

0.5 Historial para 4.3 y 4.4 (55 instancias, ~4 min). Deja el modelo desplegado
node mineria/generar_historial.js

0.6 Dejar Flowable sin instancias activas (cuentan para el limite de 5)
node scripts/escenarios/m-limpiar-instancias.js

0.7 Si recompilaste Java:
mvn package -DskipTests
docker compose restart flowable-rest flowable-ui


1. TERMINALES DE LA DEMO (una terminal por cosa; quedan abiertas)

---- Terminal A: correo de prueba (puerto 2525) ----
node scripts/escenarios/m-smtp-sumidero.js 2525

---- Terminal B: sitio web (http://localhost:3000) ----
cd web
npm install
export SESSION_SECRET="un-texto-largo-cualquiera"
npm start

---- Terminal C: simulador de la empresa (CLI, API REST) ----
export FLOWABLE_REST_USER=jefeAdmin
export FLOWABLE_REST_PASSWORD=test
mvn -q exec:java -Dexec.mainClass=unrc.cursos.simulador.SimuladorMain

---- Terminal D: app de escritorio "Preparar materiales" (API Java, Swing) ----
export FLOWABLE_DB_USER=flowable
export FLOWABLE_DB_PASSWORD=flowable
mvn -q exec:java -Dexec.mainClass=unrc.cursos.escritorio.AppMateriales

---- Terminal E: libre para comandos sueltos (fechas, limpieza, logs) ----

Fecha acordada 3 minutos en el futuro (UTC, ISO 8601) -> para "Aceptar" en el simulador
date -u -d '+3 minutes' +%Y-%m-%dT%H:%M:%SZ

Fecha acordada lejana (1 hora) -> para cancelacion / falta de aulas (que no venza el timer)
date -u -d '+1 hour' +%Y-%m-%dT%H:%M:%SZ

Ver los avisos por correo que mando el proceso
docker logs flowable-rest 2>&1 | grep Aviso

Entre un escenario y otro (borra las instancias activas de Process_Curso)
node scripts/escenarios/m-limpiar-instancias.js

EMERGENCIAS
Una solicitud nueva sale NO_VIABLE sin motivo -> hay 5 o mas instancias activas:
node scripts/escenarios/m-limpiar-instancias.js
Error al solicitar en "Evaluar Viabilidad" -> falta el DMN/modelo:
./scripts/desplegar-modelo.sh
Volver a los datos de prueba de la BD:
./scripts/crear-bd.sh
flowable-ui en Exited(1) en el primer arranque:
SMTP_PORT=2525 docker compose up -d
target/cursos-flowable.jar es una carpeta (se levanto Docker antes de compilar):
borrarla (rm -rf target/cursos-flowable.jar), luego: mvn package -DskipTests ; SMTP_PORT=2525 docker compose up -d
Permission denied en un .sh: chmod +x scripts/*.sh
No llegan correos: el SMTP de prueba (Terminal A) debe estar en 2525 y los contenedores creados con SMTP_PORT=2525
  (si cambias SMTP_PORT hay que repetir: SMTP_PORT=2525 docker compose up -d)
Puerto 3000 ocupado: ss -ltnp | grep ':3000'
"Definir docente" no se completa: la aceptacion se envio sin fecha -> volver a aceptar con fecha ISO UTC
Apagar conservando datos / borrando todo:
docker compose down
docker compose down -v      (despues repetir 0.1 a 0.4)
